# Проверки пользовательских действий

## Реализованные правила

| Сценарий | Поведение |
| --- | --- |
| Регистрация и профиль | Имя обрезается по краям; 3–50 букв, цифр или подчёркиваний. Email проверяется. Пароль при регистрации: 6–100 символов, не из пробелов или одних цифр. Пароли не обрезаются перед сохранением. |
| Фотографии | JPEG, PNG, WebP, неподвижный GIF; до 10 МиБ и 20 млн пикселей. Браузер проверяет файл до превью/сжатия. Сервер ограничивает чтение, определяет реальный формат, проверяет целостность и декодирует изображение до записи. Имя и MIME клиента не определяют расширение сохранённого файла. HEIC/HEIF нужно предварительно преобразовать. |
| Повторные действия | Формы входа и регистрации, загрузка фото, отправка комментариев и запуск примерки имеют блокировку. Общий транспорт объединяет одинаковые одновременные запросы изменения данных. Автоматического повтора записи при ошибке нет. |
| Запуск примерки | Нужны фото человека и одежды; во время обработки повторный запуск и смена одежды блокируются. Сервер читает параметры multipart-формы и проверяет их, включая NaN/Infinity. Redis блокирует одновременную отправку одинаковой примерки для одного пользователя и возвращает прежний ответ при повторе в течение 60 секунд. Существующий лимит частоты также действует. |
| Публикация | Только завершённая примерка с результатом. Подпись до 2000 символов вместе с хештегами и источником, до 20 хештегов по 64 символа. Блокировка строки сессии в PostgreSQL сериализует публикации; повтор возвращает уже созданный пост. Вещь и пост сохраняются одной транзакцией. |
| Сетевые сбои | Все API-репозитории используют тайм-аут на запрос и чтение ответа. Ошибки сети, сервера и ограничения частоты объясняются по-русски. Временный сбой проверки входа не удаляет токен: появляется кнопка повтора. |
| Сохранность данных | Подписи, хештеги и комментарии сохраняются в sessionStorage отдельно для пользователя и поста/примерки, удаляются после успешной отправки. При недоступном хранилище текст остаётся в памяти. Неотправленные фотографии можно повторно загрузить, не выбирая заново; успешные файлы из той же пачки не отправляются повторно. Аватар меняется только после сохранения. |
| Подтверждения | Удаление фотографии, вещи и результата примерки требует подтверждения. Закрытие изменённой формы профиля требует подтверждения. Закрытие/перезагрузка страницы с несохранёнными данными вызывает стандартное предупреждение браузера. |
| Сообщения | Ошибки проверки API указывают поле и правило. Восстановление пароля больше не сообщает об отправленном письме: серверная функция ещё не реализована. |

## Границы поведения

- Черновики текста сохраняются в текущей вкладке. Исходные файлы остаются в памяти до ухода со страницы; их содержимое не записывается в браузерное хранилище. Предупреждение `beforeunload` относится к закрытию и перезагрузке страницы, а не ко всем переходам внутри SPA.
- Redis-защита запуска — короткое окно от повторной отправки, а не постоянная идемпотентность. После тайм-аута сначала нужно проверить недавние примерки. При полном отказе Redis/процесса между записью задачи и кешированием ответа нет гарантии exactly-once.
- Публикация сериализуется в PostgreSQL. Локальные тесты проверяют выбор существующего поста, условия и единую транзакцию; нагрузочная проверка с реальными параллельными соединениями БД в этот набор не входит.
- Лимит файла применяется при чтении UploadFile. В комплектном nginx задан общий лимит запроса 21 МиБ (два фото плюс multipart-заголовки). При прямом доступе к backend или внешнем reverse proxy нужно настроить аналогичный лимит.

## Проверка

Автотесты: `backend/tests/test_input_safety.py`, `backend/tests/test_publication_safety.py`, `frontend/src/services/api/guardedFetch.test.js`, `frontend/src/utils/validateImage.test.js`, `frontend/src/hooks/useDraft.test.js`, тесты API-репозиториев и регистрации.

Для проверки на работающем стенде:

1. Ввести пробелы в имя/пароль, слишком длинную подпись, неверный email.
2. Загрузить пустой, повреждённый, анимированный и слишком большой файл; затем обычную фотографию.
3. Быстро нажать вход, отправку комментария, запуск примерки и публикацию несколько раз.
4. Отключить сеть при загрузке пачки фотографий, вернуть сеть и повторить неотправленные файлы.
5. Написать комментарий/подпись, закрыть диалог и открыть снова; проверить отдельные черновики разных постов.
6. Отменить подтверждение удаления; проверить, что объект остался.
7. Повторить публикацию одной завершённой примерки двумя параллельными запросами: должен вернуться один ID поста.
